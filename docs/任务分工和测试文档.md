# 任务分工和测试文档

## 1. 文档目标

这份文档用于承接 `high-concurrency-backend-plan.md` 的落地执行，明确：

- 每一类任务由谁负责。
- 各任务的交付物是什么。
- 测试怎么做。
- 什么状态算完成。

本文档默认按后端主导、前后端联动、测试配合的方式组织。如果团队人数更少，可以由同一人兼任多个角色，但任务边界不要混。

## 2. 任务分工建议

### 2.1 基础设施组

负责范围：

- Spring Boot profile 与基础设施开关收口。
- 统一 HTTP 客户端。
- 线程池治理。
- Actuator / Micrometer / 监控指标。
- Resilience4j / 超时 / 限流 / 熔断。

具体任务：

1. 梳理所有 `@ConditionalOnProperty` 默认行为，取消 `matchIfMissing = true` 的隐式启用。
2. 统一 Flask / OCR / RAG / Predict 的 HTTP 客户端实现。
3. 配置连接池、超时、重试、bulkhead、限流。
4. 增加线程池监控指标、MQ 指标、延迟任务指标。
5. 下线 `StdOutImpl` SQL 日志，补齐生产配置。

交付物：

- 配置清单。
- 基础设施能力矩阵。
- 指标面板说明。
- 压测前环境参数模板。

### 2.2 分布式架构组

负责范围：

- WebSocket 跨实例路由。
- 延迟任务平台化。
- 在线状态和实例路由状态共享。
- Agent 会话共享状态。

具体任务：

1. 改造 `WebSocketSessionManager` 为多 session 模型。
2. 落地 `userId -> instanceId` 路由表和 TTL 心跳。
3. 实现 ws 推送命令的 Redis / RabbitMQ 分发。
4. 将 `DynamicTaskScheduler` 迁移到 Redis ZSet 或 MySQL delay task。
5. 为任务消费增加幂等、重试、死信。
6. 统一 Agent session memory，移除单机内存窗口依赖。
7. 去掉工具执行链上对 `ThreadLocal` 上下文的强依赖。

交付物：

- 分布式时序图。
- WebSocket 路由方案文档。
- 延迟任务设计文档。
- 幂等和失败补偿说明。

### 2.3 Agent / AI 组

负责范围：

- Agent / RAG / OCR / Predict 提速。
- 同步和异步调用分级。
- 缓存与预热。
- 工具链收敛。

具体任务：

1. 移除 `OcrService`、`RagService`、`PredictService` 里的零散 `new RestTemplate()`。
2. 统一接入带连接池的客户端。
3. 将 `PredictService` 的硬编码地址改为配置化。
4. 将 SSE 执行切到专用 `aiExecutor`。
5. 增加 RAG / OCR / Predict 结果缓存。
6. 为 Agent 请求建立轻量同步和复杂异步两级执行模型。
7. 对常见问答做前置路由和缓存命中，减少完整 Agent 编排次数。

交付物：

- AI 调用链路图。
- 缓存键设计说明。
- Agent 路由分级规则。
- AI 压测报告。

### 2.4 数据与缓存组

负责范围：

- 索引优化。
- SQL 聚合和批量查询。
- 缓存一致性与防击穿。

具体任务：

1. 补齐 medication_task / health_data / family_member / family_event_log 等组合索引。
2. 替换药品、家庭快照、Agent session 列表中的 N+1 查询。
3. 增加批量查询 mapper。
4. 统一 Redis 缓存策略：随机 TTL、空值缓存、互斥锁、逻辑过期。
5. 修复 mapper 与表结构不一致问题。

交付物：

- 索引变更清单。
- SQL 优化前后对比。
- 热点缓存设计说明。

### 2.5 测试与压测组

负责范围：

- 功能回归。
- 性能压测。
- 故障演练。
- 多实例联调验证。

具体任务：

1. 编写 API 回归脚本。
2. 编写 k6 / JMeter 压测脚本。
3. 构建多实例测试环境。
4. 验证 WebSocket 跨实例推送。
5. 验证延迟任务不重复执行。
6. 验证 AI 服务慢/挂时的降级行为。

交付物：

- 测试用例库。
- 压测脚本。
- 压测报告。
- 故障演练记录。

## 3. 分阶段任务排期建议

### 第一阶段：压测前修正

目标：先保证系统行为正确，避免在错误实现上做性能优化。

任务：

- 修正 mapper / 表字段不一致问题。
- 修正延迟任务调度中的明显正确性问题。
- 收口基础设施开关。
- 去掉生产 stdout SQL 日志。
- 接入基础监控。

完成标准：

- 单实例功能稳定。
- 基础指标能看。
- 配置职责清晰。

### 第二阶段：连接池与线程池治理

目标：提升稳定性，避免线程和连接被慢调用拖死。

任务：

- 统一 HTTP 客户端。
- 配置 Hikari / Redis / Tomcat。
- 增加专用 aiExecutor / wsPushExecutor / domainEventExecutor / pdfExecutor。
- 给 AI 调用加并发隔离。

完成标准：

- 高并发下不会因为默认线程池或默认连接池直接雪崩。
- AI 慢调用和核心业务线程分离。

### 第三阶段：数据与缓存优化

目标：先把热点读和 N+1 压下来。

任务：

- 建组合索引。
- 改批量查询。
- 做热点缓存。
- 为 Agent / RAG / OCR / Predict 增加缓存。

完成标准：

- 查询型接口数据库压力明显下降。
- 重复 AI 请求可命中缓存。

### 第四阶段：分布式底座改造

目标：让系统具备真正的多实例运行能力。

任务：

- WebSocket 路由共享。
- 延迟任务平台化。
- Agent session 状态共享。
- 任务消费幂等、重试、死信。

完成标准：

- 多实例部署下不重复提醒、不漏推送、不丢会话。

### 第五阶段：Agent 提速与异步化

目标：把重 AI 链路和核心业务彻底隔离。

任务：

- Agent 长请求异步化。
- 简单问答前置路由。
- 缓存预热。
- 降级策略落地。

完成标准：

- Agent 高峰不会拖慢任务、家庭、健康等核心接口。

### 4.2 性能测试

#### 核心业务压测

场景：

- 登录。
- 查询今日任务。
- 更新任务状态。
- 查询药品列表。
- 查询家庭快照。

指标：

- P50 / P95 / P99。
- QPS。
- 5xx 比例。
- DB 连接池等待。
- Redis 命中率。

#### AI 压测

场景：

- 简单 Agent 问答。
- RAG 查询。
- OCR 上传。
- Predict 分析。
- SSE 并发连接。

指标：

- 外部 Flask 调用耗时。
- AI 线程池队列长度。
- 超时率。
- 缓存命中率。
- 降级触发次数。

### 4.3 分布式测试

#### 多实例 WebSocket 路由测试

步骤：

1. 启动两个 notification / gateway 节点。
2. 用户连接到 A 节点。
3. 在 B 节点触发业务事件。
4. 验证消息是否成功送达 A 节点上的连接。

通过标准：

- 跨实例推送成功。
- 不重复推送。
- 多端都能收到。

#### 延迟任务唯一消费测试

步骤：

1. 启动两个 scheduler 节点。
2. 插入同一批提醒任务。
3. 观察执行日志和结果表。

通过标准：

- 每个任务只执行一次。
- 不重复写状态，不重复推送。

#### Agent 会话连续性测试

步骤：

1. 会话第一轮打到实例 A。
2. 第二轮打到实例 B。
3. 第三轮切回实例 A。

通过标准：

- 上下文连续。
- 工具执行日志 sessionId 正确。
- 不丢历史对话。

### 4.4 故障演练测试

#### Flask 服务变慢

验证：

- Agent / OCR / RAG / Predict 是否超时受控。
- 核心业务接口是否还能正常返回。
- 限流 / 熔断是否生效。

#### Redis 异常

验证：

- 缓存失效后的回源压力。
- WebSocket 在线状态和路由的降级策略。
- 延迟任务平台如何保护核心业务。

#### RabbitMQ 异常

验证：

- 推送消息积压可观测。
- 业务主流程是否还能提交。
- 消费恢复后是否可补偿。

#### 单实例重启

验证：

- WebSocket 重连是否正常。
- 延迟任务是否丢失。
- Agent 会话是否还能继续。

## 5. 关键验收标准

### 5.1 核心业务

- 登录、任务、药品、家庭、健康核心接口保持稳定。
- 在 AI 高峰或外部依赖抖动时，核心业务不被明显拖慢。

### 5.2 分布式能力

- WebSocket 推送支持跨实例路由。
- 延迟任务支持多实例唯一消费。
- Agent 会话支持跨实例连续。
- 所有基础设施能力通过显式配置启用。

### 5.3 Agent 提速

- 简单 Agent 问答响应明显快于完整工具链请求。
- 重复 RAG / OCR / Predict 请求可命中缓存。
- AI 重请求可异步化，不阻塞主业务链路。

### 5.4 可观测性

- 能看到线程池、连接池、MQ、延迟任务、外部 HTTP 调用的核心指标。
- 能区分问题出在 Web 层、DB、Redis、MQ、Flask 还是 LLM。
