# U4: 链路追踪与可观测性 - 实现报告

## 一、需求概述

### U4.1: Sleuth + Zipkin/Jaeger (P0)
引入链路追踪组件，实现分布式调用链的可视化。

### U4.2: TraceId 日志关联 (P0)
全链路日志使用统一 TraceId，便于问题排查。

---

## 二、实现方案

### 技术选型

| 组件 | 版本 | 说明 |
|------|------|------|
| Micrometer Tracing | Spring Boot 3.2.1 内置 | Spring Boot 3.x 官方推荐的追踪方案 |
| Brave | 5.16.0 | Micrometer Tracing 的底层实现 |
| Zipkin | latest | 链路追踪 UI 和数据收集服务 |

### 为什么选择 Micrometer Tracing 而不是 Sleuth？

Spring Cloud Sleuth 在 Spring Boot 3.x 中已被弃用，官方推荐使用 **Micrometer Tracing** 作为替代方案。

### 4. MDC 配置

**文件**: [TracingConfig.java](file:///Users/motao/Desktop/MedicalAssistant/master/src/main/java/com/whu/medicalbackend/common/config/TracingConfig.java)

```java
@Configuration
public class TracingConfig {

    @Bean
    public CurrentTraceContext currentTraceContext() {
        return ThreadLocalCurrentTraceContext.newBuilder()
                .addScopeDecorator((context, scope) -> {
                    String traceId = context.traceIdString();
                    String spanId = context.spanIdString();
                    String parentId = context.parentId() != null ? context.parentIdString() : null;
                    
                    String previousTraceId = MDC.get("traceId");
                    String previousSpanId = MDC.get("spanId");
                    String previousParentId = MDC.get("parentId");
                    
                    MDC.put("traceId", traceId);
                    MDC.put("spanId", spanId);
                    if (parentId != null) {
                        MDC.put("parentId", parentId);
                    } else {
                        MDC.remove("parentId");
                    }
                    
                    return () -> {
                        // 恢复之前的 MDC 值
                        if (previousTraceId == null) {
                            MDC.remove("traceId");
                        } else {
                            MDC.put("traceId", previousTraceId);
                        }
                        // ... 类似处理 spanId 和 parentId
                        scope.close();
                    };
                })
                .build();
    }
}
```

### 5. Zipkin Server 启动

```bash
docker run -d --name zipkin -p 9411:9411 openzipkin/zipkin:latest
```

**预期日志格式（有 HTTP 请求时）：**

```
2024-05-19 15:30:01.123 [http-nio-8080-exec-1] [abc123def456] [789ghi012jkl] INFO  c.w.m.common.controller.TracingTestController - Tracing test endpoint called
2024-05-19 15:30:01.234 [http-nio-8080-exec-1] [abc123def456] [345mno678pqr] INFO  c.w.m.common.controller.TracingTestController - Simulating business logic
```

**说明：**
- `traceId` 在整个请求链路中保持不变
- `spanId` 在每个方法调用时变化
- 通过 `traceId` 可以关联同一次请求的所有日志

## 六、如何查看效果

### 1. Zipkin UI

访问：`http://localhost:9411/zipkin/`

功能：
- 查看所有请求的调用链列表
- 点击任意 trace 查看详细的调用链瀑布图
- 每个 span 的耗时一目了然
- 支持按服务名、操作名、时间范围筛选

### 2. 日志中的 TraceId

当有 HTTP 请求时，日志会自动包含 traceId 和 spanId。

**通过 TraceId 搜索日志：**

```bash
# 在日志文件中搜索特定请求的所有日志
grep "abc123def456" application.log

# 或者在控制台实时查看
tail -f application.log | grep "abc123def456"
```

### 3. API 验证

```bash
# 查看已注册的服务
curl http://localhost:9411/api/v2/services

# 查看最近的追踪数据
curl "http://localhost:9411/api/v2/traces?serviceName=mediacalbackend&limit=10"

# 查看特定 trace 的详情
curl "http://localhost:9411/api/v2/trace/{traceId}"
```

## 七、后续建议

### 生产环境配置

1. **调整采样率**
   ```yaml
   management:
     tracing:
       sampling:
         probability: 0.1  # 10% 采样率
   ```

2. **Zipkin 数据持久化**
   ```bash
   # 使用 Elasticsearch 存储
   docker run -d --name zipkin -p 9411:9411 \
     -e STORAGE_TYPE=elasticsearch \
     -e ES_HOSTS=http://elasticsearch:9200 \
     openzipkin/zipkin:latest
   ```

3. **慢接口告警（U4.3）**
   - 在 Zipkin 中配置依赖关系图
   - 对接 Prometheus + Grafana 监控
   - 配置告警规则（钉钉、企业微信、邮件等）

### 性能影响

- 链路追踪会有轻微的性能开销（通常 <5%）
- 生产环境建议调整采样率以降低开销
- 异步上报数据，不会阻塞主业务流程
