# 分布式架构优化 — 任务拆分与分工文档

> **时间**: 2 周（10 个工作日）
> **团队**: 5 名后端开发（Dev1 ~ Dev5）
> **核心约束**: 接口不变，前端不改

---

## 一、总体时序依赖

```
         Day1    Day2    Day3    Day4    Day5    Day6    Day7    Day8    Day9    Day10
Dev1     ████ U1 数据库拆分 ████ ████   ──── U6 Seata ────  ──── 集成测试 ────
Dev2     ── U2 Nacos ──  ──── U3 Feign 改造 ──────────────  ──── 集成测试 ────
Dev3     ──── U4 DomainEvent 改造 ──────────  ── U9 消息可靠性 ──  ─ 测试 ──
```

**关键路径**: Dev1 的 U1（数据库拆分）是 Dev2 的 U3（Feign 改造）和 Dev6 的 U6（Seata）的前置依赖。

## 二、各开发者任务详情

### Dev1: 数据架构师（数据层 + 分布式事务）

**角色**: 第一个完成，为其他人铺路

| 任务 | 需求用例 | 工作日 | 产出 |
|------|---------|--------|------|
| 数据库拆分方案设计 | U1.1 | 0.5天 | 分库文档、建库 SQL |
| 多数据源配置 | U1.2 | 1天 | `DataSourceConfig`、各服务 `application-*.yaml` 数据源配置 |
| 跨库查询 → Feign Client 定义 | U1.3 | 1.5天 | `common/feign/` 下各服务的 FeignClient 接口 + fallback |
| 冗余数据同步方案 | U1.4 | 1天 | Canal 配置、同步 SQL |
| Seata 分布式事务集成 | U6.1 | 1天 | Seata Server Docker 配置、`@GlobalTransactional` 示例 |
| Saga 事务编排示例 | U6.2 | 1天 | 用户注册→创建家庭的 Saga 流程 |

**产出目录**:
```
common/datasource/           # 多数据源配置
common/feign/                # FeignClient 接口定义
  ├── UserServiceClient.java
  ├── MedicationServiceClient.java
  ├── FamilyServiceClient.java
  ├── HealthServiceClient.java
  └── fallback/              # 降级类
docker/seata/                # Seata Server Docker 配置
```

**技术要点**:
- 使用 `AbstractRoutingDataSource` + `ThreadLocal` 实现动态数据源切换
- 或使用 Spring Boot 3.x 原生的 `@ConfigurationProperties` 多数据源
- FeignClient 定义在 `common` 模块，各服务引入 jar 后自动可用
- Seata AT 模式需要 `undo_log` 表，每个数据库都要加

---

### Dev2: 服务通信架构师（Nacos + Feign 调用实现）

**角色**: 在 Dev1 完成 Feign Client 定义后，负责具体改造业务代码

| 任务 | 需求用例 | 工作日 | 产出 |
|------|---------|--------|------|
| Nacos 部署 + 配置 | U2.1 | 0.5天 | `docker-compose` Nacos 配置 |
| 各服务注册到 Nacos | U2.2 | 0.5天 | `bootstrap.yaml` Nacos 配置 |
| 业务代码中的跨模块 Mapper 调用改为 Feign | U3 | 3天 | 修改 `TaskServiceImpl`, `PlanServiceImpl`, `FamilyGroupServiceImpl` 等 |
| DynamicTaskScheduler 重构 | U3 | 1天 | 移除直接 Mapper 依赖，改为 Feign 调用 |
| Nginx → Gateway 迁移（可选） | U2.4 | 1天 | Spring Cloud Gateway 路由配置 |

**产出目录**:
```
bootstrap/                   # 各服务 bootstrap.yaml 增加 Nacos 配置
medical/service/             # TaskServiceImpl 等改为注入 FeignClient
family/service/              # FamilyGroupServiceImpl 改造
common/schedule/             # DynamicTaskScheduler 重构
gateway/                     # Spring Cloud Gateway 模块（可选）
```

**技术要点**:
- `bootstrap.yaml` 配置 `spring.cloud.nacos.discovery.server-addr`
- OpenFeign 需要 `@EnableFeignClients` + `spring.cloud.openfeign.circuitbreaker.enabled=true`
- `DynamicTaskScheduler` 改造是重点难点，它同时依赖 medical/family/user 三个模块的 Mapper
- 每个 Feign 调用都要配 fallback，避免级联故障

---

### Dev3: 事件驱动架构师（DomainEvent + 消息可靠性）

**角色**: 独立于数据拆分，可并行启动

| 任务 | 需求用例 | 工作日 | 产出 |
|------|---------|--------|------|
| DomainEvent 发布改造 | U4.1 | 1.5天 | 修改 `TaskServiceImpl`, `DynamicTaskScheduler`, `FamilyGroupServiceImpl`, `HealthDataServiceImpl` |
| DomainEventHook 实现 | U4.2 | 2天 | 5 个 Hook 类 |
| 事件溯源表 + 查询接口 | U4.3 | 1天 | `domain_event` 表 + 查询 API |
| RabbitMQ confirm 模式 | U9.1 | 0.5天 | `RabbitMqConfig` 增加 confirm callback |
| 消费端手动 ACK | U9.2 | 0.5天 | 各 Listener 改为 manual ACK |
| 死信队列监控 | U9.3 | 0.5天 | DLQ 消息查看接口 |

**产出目录**:
```
common/infra/event/
  └── hooks/
      ├── MedicationAlarmHook.java      # 用药告警 → 推送
      ├── MedicationUpdatedHook.java    # 药品变更 → 缓存更新
      ├── FamilyMemberChangedHook.java  # 家庭成员变更 → 关联清理
      ├── HealthDataUpdatedHook.java    # 健康数据更新 → 快照刷新
      └── MedicationRemindHook.java     # 用药提醒 → 推送
common/infra/event/
  └── EventAuditLog.java                # 事件溯源实体
db/event_audit.sql                      # 事件审计表 DDL
```

**技术要点**:
- `ApplicationEventPublisher.publishEvent()` → `DomainEventPublisher.publish(new DomainEvent(...))`
- 事件消费者使用 `@RabbitListener` + 手动 ACK
- 每个 Hook 的 `supports()` 方法用 eventType 匹配
- 事件溯源表记录：eventId, eventType, aggregateType, aggregateId, payload(JSON), occurredAt, status

### Dev4: 服务治理架构师（分布式锁 + Sentinel + 链路追踪）

**角色**: 独立工作，不依赖其他人

| 任务 | 需求用例 | 工作日 | 产出 |
|------|---------|--------|------|
| @DistributedLock 注解封装 | U5.1 | 1天 | AOP 切面 + Redisson 锁 |
| 用药任务并发控制 | U5.2 | 0.5天 | TaskServiceImpl 加锁 |
| 家庭成员操作加锁 | U5.3 | 0.5天 | FamilyGroupServiceImpl 加锁 |
| Sentinel Dashboard 部署 | U7.1 | 0.5天 | Docker Compose 配置 |
| 接口限流规则 | U7.2 | 0.5天 | Sentinel 限流配置 |
| Feign 熔断降级 | U7.3 | 1天 | FeignClient fallback 实现 |
| Sleuth + Zipkin 集成 | U8.1 | 1天 | 依赖 + 配置 |
| TraceId 日志关联 | U8.2 | 0.5天 | logback 配置 MDC traceId |
| 慢接口告警 | U8.3 | 0.5天 | Sentinel 慢调用规则 |

**产出目录**:
```
common/lock/
  ├── DistributedLock.java              # 注解
  ├── DistributedLockAspect.java        # AOP 切面
  └── LockKeyResolver.java             # SpEL 键解析
docker/sentinel/                        # Sentinel Dashboard Docker
docker/zipkin/                          # Zipkin Docker
common/config/
  ├── SentinelConfig.java              # Sentinel 初始化
  └── SleuthConfig.java               # 链路追踪配置
```

**技术要点**:
- `@DistributedLock` 基于 Redisson `RLock`，AOP 切面拦截注解方法
- SpEL 解析锁键：`@DistributedLock(key="#taskId")`
- Sentinel 限流通过 `@SentinelResource(value="xxx", blockHandler="yyy")` 声明
- Sleuth 在 Spring Boot 3.x 中已合并到 `micrometer-tracing`，用 `spring-cloud-starter-zipkin`
